# 권한과 규칙 변경

## GOV-001

승인된 규칙은 기존 작업 권한 안에서 에이전트가 자율 적용한다. 적용은 명시된 목적과 조건에 따른다. 새로운 외부 효과나 작업 범위까지 허용된 것으로 해석하지 않는다.

증거: 작업 계약의 적용 규칙·범위·실행 권한 참조. 이 문서는 실행 권한을 기술적으로 부여하지 않는다.

## GOV-002

규칙의 실질적인 추가·수정·폐기·예외는 BOSS 확인 이후 적용한다. 개정안 작성은 가능하지만 기존 승인 규칙과 섞지 않는다. 개정 시 변경 이유, 동일 사례에 대한 변경 전후 판정, 영향과 비용, 적용 시점·진행 중 작업 처리·되돌림 조건을 제시한다.

통과 후 문제 발생, 정상 변경의 오탐 차단, 요구·환경 변화, 규칙 충돌, 지표와 실제 결과의 불일치, 중복은 재검토 신호다. 자동 개정 조건은 아니다. 승인 근거는 [승인 기록](approvals.md)에 남긴다.

## GOV-004

현재 작업을 통과시키려고 기대값·임계값·검사 범위를 임의로 바꾸거나 필수 검사를 삭제하지 않는다. 검사 오류도 제품 문제와 구분해 재현하고 변경안을 제시한다. 승인된 기준 변경 후 해당 대상에 재검증한다.

증거: 요구사항·검사·규칙 diff, 검사 오류 재현, 변경 승인 참조. 실행 코드 수정과 규칙 변경의 구분에는 사람 또는 검토자의 의미 판단이 필요하다.

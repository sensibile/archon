# 리뷰 반복 종료·상향 기준 개정안

상태: 2026-10-28 BOSS 확인으로 승인. 현행 본문은 [검증과 측정](../verification.md#ver-005)의 VER-005 1.0이며 승인 범위는 [승인 기록](../approvals.md#approval-2026-10-28)을 따른다. 이 문서는 개정 근거로 보존하며 실행 권한을 부여하지 않는다.

작성: 2026-10-28. 근거: 같은 날 BOSS가 Phase 2 종료 조건과 상향 조건을 공통 기준으로 확정했다. 이어서 이 기준을 `docs/rules`의 정식 규칙으로 등록하기로 결정하면서, 등록은 별도 개정안으로 하라고 지시했다. 확정 내용은 [작업 단계](https://github.com/sensibile/taeguk/blob/9119a54c4ead760e8620df57765dc6b8799ab478/codex/skills/taeguk-work-contract/references/phases.md)에 운영 기준으로 반영되어 있다. 이 개정안은 그 기준을 규칙 ID와 버전으로 고정하기 위한 것이다.

## 현행 규칙과 공백

- VER-003 1.0: 상태 다섯 가지를 구분하고 미실행을 성공으로 보지 않는다. 다만 어떤 미확인 항목이 완료를 막는지는 "해당 작업의 승인된 필수 기준"에 맡긴다. 리뷰 지적에 대한 공통 기준은 없다.
- [목적에 대한 완료 검토](https://github.com/sensibile/taeguk/blob/9119a54c4ead760e8620df57765dc6b8799ab478/codex/skills/taeguk-work-contract/references/completion-review.md): "새 규칙이나 공통 통과 기준이 아니다"라고 명시한다.
- DEV-002 1.1: "공통 작업 크기·재시도 수치를 새로 강제하지 않는다."
- GOV-005 0.1(제안): 작업·정리·재시도 한도 후보다. 전역 횟수·시간·예산은 합의하지 않았다.
- REQ-006 1.0: 대상이 바뀌면 다시 검증한다. Phase 3 구조 변경 뒤의 재검증은 이 규칙으로 이미 요구되므로 새 규칙이 필요 없다.

작업 계약에 리뷰 지적 기준이 없으면, 리뷰를 몇 번 돌려야 끝나는지 정할 근거가 없다.

## 문제 사례

2026-10-28 실제로 관측한 사례다. 리뷰 원시 출력은 그 세션의 로컬 작업 디렉터리에만 남았고 저장소에는 보존하지 않았다. 각 PR 본문의 검증 표는 일부 회차만 요약한다. #22의 3차 지적은 PR 본문 초판에만 적혀 있었고, 이후 본문을 고치면서 빠졌다.

1. [sensibile/taeguk#22](https://github.com/sensibile/taeguk/pull/22): 로컬 교차 리뷰를 다섯 번 돌렸다. 1차 P1 1건, 2차 P2 1건, 3차 P2 1건(이 PR 범위 밖의 의존), 갱신 뒤 4차 P2 2건이 나왔고 5차에 지적이 없었다. 매 회차가 이전 수정에서 나온 새 지적이었고, 언제 멈출지는 세션의 판단에 맡겨졌다.
2. [sensibile/taeguk#23](https://github.com/sensibile/taeguk/pull/23): 1차 리뷰가 "P0·P1 0건"과 "같은 지적 두 번" 기준을 승인되지 않은 기준이라고 지적했다(P2). 현행 규칙에 공통 기준이 없으니 지적 자체는 맞았고, BOSS 확인이 필요했다.
3. [sensibile/taeguk#21](https://github.com/sensibile/taeguk/pull/21): GitHub Codex가 P1("스킬을 한국어로 작성")을 냈다. 기존 스킬 11개가 영어로 된 에이전트 지침이라 평가 역할이 근거를 들어 기각했다. Codex의 P 등급만으로 판정하면 이 PR은 막혔다.

## 개정안: VER-005 1.0 (신규)

ID: archive 후보 VER-001·VER-002, 현행 VER-003·VER-004와 겹치지 않도록 VER-005를 쓴다.

제안 본문:

> 검증·리뷰·수정을 반복하는 단계는 다음을 모두 만족하면 끝낸다. 필수 검사가 VER-003 기준으로 PASS다. 평가 역할이 확정한 P0·P1 지적이 0건이다. P2 이하 지적은 반영했거나 반영하지 않은 이유를 기록했다. 작업 계약에 승인된 수용 기준이 이보다 엄격하면 그 기준을 따른다.
>
> 지적의 등급은 리뷰 도구가 붙인 등급이 아니라 평가 역할이 코드와 승인된 요구사항에 비춰 확정한다. 등급을 낮추거나 기각할 때는 이유를 기록하고 PR이나 작업 기록에 남긴다.
>
> 같은 지적이 두 번 되풀이되거나 수정이 다른 지적을 계속 낳으면 반복을 멈추고 BOSS에게 상황과 선택지를 보고한다. 이 보고는 작업 중단이나 실패 판정이 아니다. 기준을 낮춰 통과시키지 않는다(GOV-004).
>
> 증거: 회차별 리뷰 대상 SHA, 지적 목록, 평가 역할의 등급과 처리, 상향 보고 기록. 스킬: taeguk-work-contract, taeguk-codex-local-review.

## 변경 전후 판정

## 다른 규칙과의 관계

- VER-003: 종료 판단에 필요한 공통 기준을 보탠다. 상태 구분은 바꾸지 않는다.
- DEV-002의 "공통 재시도 수치를 강제하지 않는다": VER-005는 반복 횟수 상한이 아니다. 같은 주장이 두 번 되풀이되면 보고하라는 조건이며, 몇 번 반복할 수 있는지는 정하지 않는다. "두 번"이라는 수치는 2026-10-28 BOSS가 공통 기준으로 확정했다.
- GOV-005(제안): 범위·시간·비용 한도는 계속 제안 상태로 둔다. VER-005는 리뷰 지적 반복만 다룬다.
- completion-review 참고 문서의 "공통 통과 기준이 아니다"라는 문장은 VER-005 승인 뒤 "VER-005 외의 공통 통과 기준은 없다"로 바꾼다.

## 비용과 권한 영향

- P2 이하 결함이 이유 기록만으로 남을 수 있다. 실제 결함을 미룬 경우가 나중에 발견되면 되돌림 신호로 본다.
- 평가 역할의 등급 재분류가 기준의 실질을 정한다. 재분류 이유를 PR 본문에 남겨 BOSS가 사후에 볼 수 있게 한다.
- 새 실행 권한, 외부 전송, 자동 승인을 만들지 않는다. 기계 검사도 추가하지 않는다.

## 전환과 되돌림

전환:

1. BOSS 확인 후 `verification.md`에 VER-005 1.0 본문, registry 항목(approved), 승인 기록을 같은 변경으로 추가한다.
2. [작업 단계](https://github.com/sensibile/taeguk/blob/9119a54c4ead760e8620df57765dc6b8799ab478/codex/skills/taeguk-work-contract/references/phases.md)의 "등록 대기" 문장을 VER-005 참조로 바꾸고, completion-review 문장을 위와 같이 고친다.
3. 승인일 이후 새로 시작하는 작업부터 적용한다. 진행 중인 작업은 기존 판단을 유지하고, 채택할 때 기록한다.
4. 시험 프로젝트에는 다음 설치 갱신 때 규칙 스냅샷으로 전달한다. 설치 dry-run 확인과 프로젝트별 BOSS 승인을 거친다.

되돌림 신호: 이유를 기록하고 넘긴 P2가 나중에 실제 결함으로 반복 발견됨, 등급 재분류가 잦거나 근거가 약함, 상향 보고가 너무 잦아 작업이 멈추거나 반대로 한 번도 쓰이지 않음. 신호는 자동 되돌림 조건이 아니며 GOV-002 재검토로 다룬다. 되돌릴 때는 VER-005를 retired로 바꾸고 작업 단계 문서를 작업별 기준으로 복원한다.

## BOSS 확인 사항

1. VER-005 1.0 채택 여부.
2. 등급 확정 주체: 리뷰 도구의 등급이 아니라 평가 역할이 확정하고, 낮추거나 기각할 때 이유를 남기는 방식이 맞는지.
3. 상향 조건은 확정된 문구를 그대로 옮겼다. "같은 지적"을 "같은 위치의 같은 결함 주장"으로 좁힐지는 별도로 정한다. 좁히면 위치가 바뀐 재발이 보고 대상에서 빠지므로 의미 변경이다. 이 개정안은 좁히지 않는다.
4. 적용 범위: 다른 규칙과 같이 "Taeguk and explicitly assigned workflows"로 둘지.

# 개발 작업 공간

## DEV-003

저장소 파일을 바꾸는 개발 작업(구현·수정·리팩터링·테스트·추적 문서)은 첫 편집 전에 그 작업 전용 git worktree와 작업 브랜치를 만들고, 구현과 검증을 그 안에서 한다. 읽기·리뷰·계획만 하는 작업에는 적용하지 않는다. 측정 전용 워크트리에서 커밋하지 않고 되돌리는 임시 편집(예: 결함 주입)은 개발 편집이 아니다. 이 편집은 메인 checkout과 다른 작업의 워크트리 밖에서 하고, 끝나면 원복을 확인한다.

base는 사용자가 정한 것, 저장소 규약, 원격에서 확인한 대상 브랜치 SHA 순으로 정한다. 로컬 추적 ref만으로 최신이라고 보지 않는다. 브랜치 이름은 저장소 규약을 따르고, 규약이 없으면 `<type>/<slug>`를 쓴다. 위치는 저장소 규약을 따르고, 규약이 없으면 checkout 바깥의 `<저장소 이름>-worktrees/<slug>`를 쓴다.

같은 작업의 후속은 그 작업에 배정된 워크트리를 다시 쓴다. 관련 PR이 머지되거나 닫혔으면 새 작업으로 보고 새 워크트리를 만든다. 실행 환경이 그 세션용으로 만든 워크트리는 작업 브랜치를 만든 뒤 그 작업의 워크트리로 쓴다.

메인 checkout, 다른 작업의 워크트리, 커밋하지 않은 변경을 보존한다. 이름·경로 충돌을 강제 옵션이나 삭제로 넘기지 않는다. 워크트리를 만들 수 없으면 메인 checkout에서 몰래 진행하지 않고 원인을 보고한다.

증거: 작업 기록이나 PR의 base SHA, 브랜치, 워크트리 경로. 스킬: taeguk-implement-small-change, taeguk-self-improve. 사용자의 명시 지시가 우선한다. 워크트리 정리 시점과 방법은 정하지 않는다.

적용 범위는 Taeguk과 이 규칙 사본이 설치된 프로젝트의 모든 저장소 편집이다. 태극 작업으로 지정되지 않은 일반 개발도 포함한다. 프로젝트 `AGENTS.md`에 워크트리 규약(경로·이름·재사용)이 있으면 그것이 이 규칙의 기본값보다 우선한다. 문서 지침이며 편집 위치를 기계적으로 막지 않는다.

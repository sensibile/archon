# 목적에 대한 완료 검토

REQ-001·REQ-006·VER-003·VER-004를 적용하는 선택적 작업 방법이다. 새 규칙이 아니며, 리뷰 반복의 종료 기준인 VER-005 외에 공통 통과 기준은 없다. 승인된 기준이 부족하면 부족하다고 설명하고 제안 상태로 남긴다.

## 먼저 답할 질문

사용자가 이 결과로 이해하거나 실행하려는 것을 적고, 산출물에서 그 답을 어디서 확인할지 연결한다. 입력 처리·계산 정확성·사용자 질문에 대한 답·전달·실제 사용 효과를 구분한다. 같은 검사가 모두를 증명한다고 보지 않는다. 실제 사용 전에도 구현이나 분석 단계가 완료될 수 있지만 어느 단계인지 밝힌다.

분석은 합계 표에서 멈추지 말고 판단을 바꿀 가능성이 큰 항목을 조사한다. 금액·빈도·반복 패턴·출처를 묶어 가설과 반례를 비교하되, 근거와 분류 확정을 구분한다. 제품은 사용자가 해야 할 확인 작업과 재사용 흐름까지 살펴본다. 비교 가능한 관측이 없으면 시간 절감이나 품질 개선을 주장하지 않는다.

## 미결 사항을 인계하는 방법

결론에 미치는 영향, 확인한 자료와 조사 결과, 남은 대안, 해결에 필요한 다음 행동을 묶는다. 해소하지 못했다면 이유를 명시한다. 사용자만 알 수 있는 사실과 도구로 더 조사할 수 있는 사실을 구분한다. 반복 항목은 근거가 같을 때 묶어 확인 부담을 줄이고, 영향이 큰 항목부터 제시한다. 불확실성을 이유로 원래 과제를 다음 과제로 축소하지 않는다.

예: 양수 거래를 단순히 “환불 미확인”으로 나열하는 대신 원거래 후보·날짜·금액 대조를 해 보고 확인된 연결과 남은 의문을 나눈다. 연결 근거가 부족하면 확정하지 않는다. 이 예는 금융 분류나 임계값에 대한 공통 규칙이 아니다.

## 마감 인계

원래 요청의 각 결과를 충족·부분 충족·미실행으로 설명하고 해당 검사와 실제 산출물을 연결한다. 구현 테스트 통과는 해석의 타당성이나 검토 노동 감소를 대신하지 않는다. 확인되지 않은 실제 효과와 현재 단계 완료를 따로 쓴다. 검토자는 가능하면 구현자의 결론을 받기 전에 요청·원시 자료·산출물에서 빠진 답을 찾아본다. 위임 권한이 없는 경우 자체 검토임을 밝힌다.

`taeguk audit REVIEW.json ROOT`는 선택적 증거 연결 보조다. 검사 ID·요구사항 연결과 파일 hash를 확인하지만 내용의 관련성·실행 진실성·사용자 효과를 판정하지 않는다. 선언만으로 만든 예제를 실제 과제의 검증으로 보고하지 않는다. 실제 사용법과 입력 예시는 Taeguk 저장소의 `docs/evidence-review.md`에 있다. 저장소가 없는 설치 환경에서도 위 작업 방법은 사용할 수 있다.

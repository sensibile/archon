# ADR 0019: 태극 번들 갱신과 Codex 리뷰 목적 맥락 적용

- 상태: 제안
- 날짜: 2026-10-30
- 태극 원본: sensibile/taeguk `b7b4b581c27a70be13f521cb6f30fb2fc29e64bf`(sensibile/taeguk#38 머지 커밋)

## 맥락

로컬 Codex 리뷰가 upstream 동작이나 Phase 범위 때문에 의도적으로 미룬 것을 계속 지적해 리뷰가 길게 반복됐다.
archon #31에서는 Codex 지적 5건 중 3건이 upstream 동작이나 ADR 0014의 Phase 범위를 이유로 기각됐고, 기각한
지적이 재리뷰에서 다시 나왔다. Codex는 diff와 저장소만 보고 요청과 결정 기록은 보지 않으므로, 변경의 목적이
아니라 일반적인 관행에 비춰 판단한다.

태극 #38은 `taeguk-codex-local-review` 스킬과 `references/review-prompts.md`, `taeguk_codex_cross_reviewer`·
`taeguk_codex_security_reviewer` 역할을 고쳐 이 문제를 다룬다.

- 프롬프트에 목적 맥락 블록(목적, 요구사항, 정답 기준, 미룬 범위와 근거 기록, 도달 경로와 입력 신뢰 주체)을
  반드시 넣는다. 목적이나 정답 기준이 기록에 없으면 지어내지 않고 NOT_RUN으로 남긴다.
- 재리뷰 때는 고치지 않은 지적을 대상 head, 상태, 이유와 함께 넘긴다.
- 프롬프트 파일을 출력과 함께 증거로 남기고 `shasum -a 256` 해시를 PR 본문에 적는다.
- 목적·정답 기준·미룬 범위 자체를 문제 삼는 목적 이의는 기각하지 않고 BOSS에게 넘기며, 답이 오기 전에는 그
  head에 auto-merge를 켜지 않는다.

BOSS는 2026-10-30 #38 머지 뒤 archon 번들 갱신을 승인했다. archon에 설치된 번들은 `a820b4a`(ADR 0017)다.

## 결정

1. **태극 번들을 `b7b4b58`로 갱신한다.** 설치기는 `scripts/taeguk_install.py project --root <worktree> --agent codex,claude`다.
   - dry-run: `installer_version` `b7b4b58`, `installed_versions`는 세 구성요소 모두 `a820b4a`. rules·codex·claude가
     모두 `planned`(14·63·47 파일)이고, 경고와 `shadowed_by_user_skills` 항목은 없었다. 적용 직전에 다시 돌린
     dry-run 출력도 같았다.
   - `--apply` 뒤 `--check`: rules·codex·claude 모두 `verified`(14·63·47), 설치 버전은 세 구성요소 모두 `b7b4b58`.
   - 내용이 바뀐 파일: `taeguk-codex-local-review` 스킬과 `references/review-prompts.md`(`.claude/skills/`,
     `.agents/skills/`), 교차·보안 리뷰 역할(`.claude/agents/`, `.codex/agents/`). `.taeguk/rules/`의 4개 파일은
     태극 원본 링크의 고정 SHA만 바뀌었다.
   - 설치본은 직접 고치지 않는다(ADR 0007 결정 3).
2. **archon의 목적 맥락 기본값을 정한다.** 스킬은 목적 맥락을 구현이 아니라 작업 계약, 승인된 요구사항, 결정
   기록에서 가져오라고 한다. archon에서 각 칸의 기본 출처는 다음과 같다. 작업마다 더 구체적인 기록이 있으면
   그것을 쓴다.

   | 칸 | archon 기본값 |
   |---|---|
   | 목적 | 그 작업의 요청과 해당 단계 ADR의 맥락. 포팅 작업은 ADR 0003의 "외부 계약은 유지하고 내부는 다시 설계" |
   | 요구사항 | 해당 단계 ADR의 결정과 조각·범위 표(예: ADR 0014 결정 8의 조각 표) |
   | 정답 기준 | upstream conductor-oss의 동작과 테스트. 기준 SHA는 각 단계 ADR 머리말에 있다(현재 `1488804170d159021c7e62dce61514b8f31ef9ff`). 외부 계약은 `priv/contract/`. 각 단계 ADR의 "정답 기준" 절이 있으면 그것을 우선한다 |
   | 미룬 범위 | ADR 0014와 각 Phase ADR의 조각·범위 표에서 뒤로 미룬 항목, 그리고 "upstream과 의도적으로 다른 점" 절. 칸마다 근거 ADR과 절을 적는다 |
   | 도달 경로·입력 신뢰 주체 | 기록에서 가져오지 않고 바뀐 코드의 호출자와 진입점을 직접 확인해 경로와 함께 적는다. Phase 5(REST) 전에는 외부 진입점이 없다는 것도 확인한 사실로 적는다 |

   - 저장소 운영 변경(번들 갱신, 문서, 설정)은 정답 기준을 그 결정의 ADR과 태극 원본 커밋으로 둔다.
   - 데일리 워커는 스킬이 정한 대로 워커 스킬과 [운영 문서](../operations.md)의 BOSS 승인 기록을 작업 계약으로 쓴다.
     정리 항목의 정답 기준은 "동작 변화 없음", 테스트 보강은 각 테스트가 인용한 출처다.
3. **AGENTS.md "PR과 머지"에 목적 맥락과 목적 이의 게이트를 넣는다.** 1단계는 리뷰를 태극
   `taeguk-codex-local-review` 절차에 맡기므로 목적 맥락과 프롬프트 해시는 갱신된 스킬로 적용된다. 하지만 2단계는
   auto-merge를 켜지 않는 조건을 "NOT_RUN이나 UNKNOWN"으로만 적고 "끝났으면 켭니다"로 잇는다. 새 스킬의 "답 없는
   목적 이의가 있으면 켜지 않는다"는 이 목록에 없어서, AGENTS.md만 읽는 에이전트는 목적 이의가 남은 head에
   auto-merge를 켤 수 있다. 태극도 자기 저장소 운영 문서의 같은 단계에 이 조건과 프롬프트 해시를 넣었다.
   - 1단계: 프롬프트에 목적 맥락을 넣고(기본값은 이 ADR 결정 2), 재리뷰 때 고치지 않은 지적을 상태·이유와 함께
     넘기고, 프롬프트 sha256을 PR 본문에 적는다. 목적 이의는 기각하지 않고 BOSS에게 넘긴다.
   - 2단계: auto-merge를 켜지 않는 조건에 "BOSS가 답하지 않은 목적 이의"를 더한다.
   - PR 템플릿의 로컬 Codex 리뷰 칸에 "프롬프트 sha256"을 더한다.
   - AGENTS.md 문구 변경은 BOSS 승인 사항이다. 2026-10-30 이 작업 세션이 PR을 만들기 전에 초안을 보고했고,
     BOSS가 "초안대로 승인"이라고 답했다.

## 대안

- **AGENTS.md를 그대로 두고 스킬에만 맡기기:** 1단계가 스킬을 부르므로 동작은 같아야 하지만, 2단계의 조건 목록이
  닫힌 목록처럼 읽혀 목적 이의 게이트가 빠질 수 있다. 게이트를 놓치면 리뷰하지 않은 목적 문제가 머지되므로
  문구를 맞추는 쪽을 택한다.
- **목적 맥락 기본값을 AGENTS.md에 직접 쓰기:** 기준 SHA와 범위 표는 단계마다 바뀌므로 ADR에 두고 AGENTS.md는 이
  ADR을 가리키게 한다.
- **#38만 골라 설치:** 설치기는 원본 커밋 하나를 통째로 설치한다. `a820b4a` 이후 태극 변경은 #38뿐이다.

## 결과

- 목적 맥락을 넣은 Codex 리뷰가 기각된 지적의 반복을 실제로 줄이는지는 이 PR 이후 리뷰의 회차 수와 반복 지적
  기록으로 확인한다. 아직 관측하지 않았다.
- 목적 이의 게이트와 프롬프트 해시는 스킬 문서 지침이고 기계적으로 강제되지 않는다.
- 진행 중인 다른 세션(Phase 3 ADR 0018)의 리뷰에는 이 PR이 머지된 뒤 다음 Codex 회차부터 적용된다.
- 이 ADR은 구현 PR이 머지된 뒤 다음 PR에서 승인으로 바꾼다.
